# Vibe Coding Mastery & Agent Orchestration

> [!info] Methodology Thesis
> **Vibe Coding** is not lazy coding — it is **high-leverage systems engineering**. The modern engineer does not spend hours memorizing syntax or typing boilerplate. The modern engineer acts as the **Director, Architect, and Commander**, using autonomous AI agents to execute code at machine speed.

## Dhruv's Rules of Vibe Coding

### Rule 1: Be the Conductor, Not the Typist
- Never write 50 lines of boilerplate by hand when an agent can scaffold it in 3 seconds.
- Spend 80% of your energy on **architecture, data models, edge cases, user experience, and business logic**. Let AI write the syntax.

### Rule 2: Ground the AI with Strict Rules
- Always give agents an index or spec file (`AGENTS.md`, `CLAUDE.md`, `INDEX.md`).
- Constrain directory structure and dependencies early to prevent AI hallucinations.

### Rule 3: The Ponytail Principle (Anti-Overengineering)
- Follow [[Ponytail - Pragmatic Minimal Engineering]]: reach for native platform tools and standard libraries first. The simplest solution that works is the superior solution.

### Rule 4: Automated Verification
- Use self-repair loops ([[Autonomous Agent Self-Repair Loop]]) where tests and linters give AI feedback, so the agent fixes its own mistakes without human frustration.

## Active Tools in Dhruv's Stack
- **Google Antigravity**: Agentic pair programming and workspace management.
- **Claude Code (CLI)**: Rapid terminal refactoring and repository navigation.
- **DENIEL**: Local laptop autonomous agent with Ollama.
- **Cursor / Windsurf**: Real-time AI IDE orchestration.
